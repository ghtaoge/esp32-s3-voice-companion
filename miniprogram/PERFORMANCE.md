# 小程序合成负载复核

本机 Node v24.16.0；2026-11-06。运行 `npm run benchmark` 可重现当前版本的协议、计时器和视图桥负载。以下对比是在相同合成输入下分别运行修复前后代码所得，**不调用 ASR 模型，不代表手机原生渲染 FPS、网络吞吐量或模型识别延迟**。

## 持续流式更新

初始 160 句历史，每句 320 字；30 秒虚拟时间内注入 600 次字幕修订、3000 次音量更新、30 次情绪消息。视图桥完成回调刻意延迟 120 ms，用于检查慢视图下的队列增长。

| 项目 | 修复前 | 修复后 |
| --- | ---: | ---: |
| `setData` 调用 | 3930 | 151 |
| 累计序列化 payload | 1,358,231 B | 532,409 B |
| 最大待完成视图更新 | 17 | 1 |
| 不必要的设置草稿更新 | 630 | 0 |
| 保留的历史分句 | 160 | 160 |
| 视图历史序列化大小 | 353,272 B | 199,128 B |
| 最后一个字幕修订 | 600 | 600 |

单次 Node 工作耗时为修复前约 394 ms、修复后约 86～121 ms，包含 JSON 编解码及桥模拟；主机负载、JIT 和 GC 会影响时间，计数与 payload 上界更适合作为回归约束。正常手机桥回调通常不同于此处人为设置的 120 ms，因此不能把 151 次更新换算为实际手机 FPS。

## 长快照与连接风暴

| 合成场景 | 修复前 | 修复后 |
| --- | ---: | ---: |
| 160 句 × 2048 字快照的最大单次视图 payload | 2,009,811 B | 205,649 B |
| 同一大快照重复 30 次的 `setData` 调用 | 90 | 2 |
| 3000 个入站包触发的计时器创建 | 3002 | 2 |
| 60 秒内反复建立又立即断开、重复上报错误的连接尝试 | 75 | 8 |
| 连接管理器切后台后残留计时器 | 0 | 0 |

极长快照按 64K UTF-16 总文字预算保留最近 32 个完整分句；常见短句仍可保留 160 句。没有裁切半个 emoji，也没有将过期临时结果覆盖最终结果。此预算只控制手机显示缓存，电脑历史按后端自身保留配置保存。

修复包括：仅在设置消息变化时同步草稿；字幕、情绪与音量共同归并；视图只保留一条待完成更新；复用未改变的分句视图；移除视图中重复的整段录音全文；限制历史总文字；重复快照归并后再裁剪；入站消息只更新最后接收时间；短暂建立连接不重置重连退避；前后台渲染回调按代际隔离。

新增资源回归测试验证这些上界、最终修订号和退出后台后的清理。脚本中的进程 GC 后堆差值只是 Node 观测值，不能用来推算手机内存占用；实际手机性能仍需用真机开发工具复核。
