# 微信小程序

小程序直接连接电脑本地网关，接收 FunASR 的实时字幕、断句结果与 SenseVoice 情绪标签；屏幕设置也经电脑发送给开发板。音频由 INMP441 → ESP32 → 电脑传输，不经过小程序或 BLE。录音由开发板 BOOT 按钮控制：**按住说话，松开结束**。

## 导入与连接

1. 在电脑启动项目后端，等待模型就绪，查看电脑显示的配对信息。
2. 公开源码只使用 `touristappid`。需要真机预览时，在本目录执行 `node scripts/prepare.js --appid 你的小程序AppID`，再在微信开发者工具中导入 **`miniprogram/.local/wechat/`**。这个副本被 Git 忽略，不会把个人 AppID 放进公开项目。每次更新源码后重新运行准备命令。
3. 使用具有该 AppID 开发权限的微信账号预览。让手机、电脑、ESP32 处于同一可互通的局域网。电脑可以有线连接；手机使用能访问电脑的 Wi-Fi。
4. 小程序点击“扫码配对”，扫描电脑给出的配对二维码；或手动输入 `ws://电脑局域网IP:8765`、设备标识、配对口令，再点“连接电脑”。示例地址 `ws://192.168.1.100:8765` 只是格式示意，需要换成电脑实际地址；手机不能用 `127.0.0.1` 访问电脑。
5. 电脑和开发板都在线后，按住开发板 BOOT 说话，再松开。临时字幕会被同一句最终结果覆盖，随后到达的情绪标签会补在对应句子下面。

扫码接受电脑生成的 JSON：

```json
{"url":"ws://192.168.1.100:8765","device_id":"esp32-s3","token":"由电脑本地生成的配对口令"}
```

也接受完整的小程序连接地址 `/ws/client/{device_id}?token=...`。不要把真实配对信息放入源码、公开截图或 GitHub issue。“记住连接”会把电脑地址、设备标识与配对口令保存在当前微信的本地存储中；关闭此开关立即清除已保存信息。字幕历史来自电脑，手机端只保留当前会话内的有界缓存。

## 局域网与微信配置

微信支持同网段、非手机本机 IP 的局域网 WebSocket 连接；此场景不需要公网中转服务。电脑需监听可访问的网卡地址，并放行本地网关端口，路由器不能开启设备隔离。局域网能力与开发工具的“不校验合法域名”调试选项是两回事，不能仅靠调试模式成功就判断正式真机可用。

- iOS 首次连接可能请求微信的“本地网络”权限；拒绝后应到手机系统设置授权。
- 口令错误可能表现为 HTTP 403 握手失败或连接关闭，不同终端的错误反馈不一致。连续握手失败时页面会提示检查服务、地址、网络、防火墙和口令，并保持退避重连，不把网络故障直接判定为认证失败。若已建立的连接明确收到策略拒绝关闭码，则停止自动重试，等待用户修改连接信息。
- 默认使用输入地址或扫码，不依赖 mDNS，避免客户端发现能力差异。
- 跨网使用时，需要按微信普通网络规则配置可达的 WSS 域名与可信证书，同时增加适合外网的访问控制。此项目默认用于局域网。
- 如果启用“扫码配对”，请按当前 AppID 后台要求完成用户隐私保护指引，声明扫码/相机用途。页面提供原生 `agreePrivacyAuthorization` 同意按钮；拒绝扫码授权仍可手动填写。小程序不申请麦克风和蓝牙权限，不上传相机图像到电脑或云端。

参考：[微信局域网通信](https://developers.weixin.qq.com/miniprogram/dev/framework/ability/mDNS.html)、[微信网络说明](https://developers.weixin.qq.com/miniprogram/dev/framework/ability/network.html)。

## 字幕与设置行为

- 字幕以 `recording_id + segment_id` 定位，以 `revision` 拒绝迟到的旧结果。最终文本覆盖对应临时字幕，不重复追加；分句结束不等于松键结束整次录音。
- 情绪显示模型返回的标签与事件。没有标签时显示“未识别”，跳过或失败分别显示对应状态，不从文字关键词推断，也不显示模型未提供的置信度。
- 情绪结果晚到时更新原句，不影响新的录音状态；重连快照会补齐最近字幕和已经完成的情绪分析。
- 设置页面显示“设备当前设置”和独立草稿。点击应用后等待开发板 ACK；收到 `settings_applied` 才报告已应用。超时、断线和设备离线不会假装保存成功。断线后草稿保留，重连读取实际值，用户可以“恢复设备当前设置”。
- 手机退到后台时主动关闭 WebSocket，停止重连与心跳；回到前台时重连并补齐快照。主动断开后，本次页面不自动重连。

## 性能

小程序只处理文字与低频状态，不参与实时采音或 ASR。字幕、情绪与音量先在内存归并，视图最多每 80 ms 更新一次，并且始终只有一个字幕 `setData` 在等待完成。视图较慢时发送最新归并状态，不积压旧帧。普通流式更新只传改变的分句；历史视图复用缓存，不把整段录音全文再重复放进视图数据。完整文字仅在用户点击复制时拼接。

前台心跳与失活检测只保留有界计时器，入站包只更新时间戳，不为每个音量/字幕包重建定时器。刚连上就断开的连接保留退避；稳定连接超过 10 秒后再次断线才重新从短间隔开始。旧连接回调和旧页面渲染回调不能触发后台重连或释放新一轮渲染锁。

历史同时受两个限制：最多 160 个分句、总文字最多 64K UTF-16 单元（大部分汉字占 1 单元，emoji 通常占 2 单元），每句最多 4096 个 Unicode 字符。超出总预算时从最旧的分句移除，避免长快照超过小程序单次视图更新容量。此裁剪只影响手机显示缓存，电脑历史按后端自身的保留配置保存。重复快照先归并再裁剪，保留较新的修订和正确顺序。

可以用 `npm run benchmark` 重现合成负载：50/160 句历史、30 秒虚拟流量中的 600 次字幕更新＋3000 次音量更新＋30 次情绪消息、重复大快照、WebSocket 心跳和开关连接风暴。输出包括 `setData` 次数/字节、最大待完成视图数、计时器数量、连接尝试次数与 Node 处理耗时。此脚本不调用 ASR 模型，Node 数字不代表手机原生渲染速度或实际网络吞吐量。

## 验证

无需 npm 依赖，在本目录执行：

```powershell
npm test
```

测试覆盖两遍结果覆盖、迟到包、情绪乱序与重连补齐、有界 UTF-8 文本、配对地址校验、设置 ACK、后台生命周期、重连退避和心跳断线检测。

有微信开发者工具时，可额外指定官方 `wcc.exe`，测试会实际编译并渲染 WXML，检查设置按钮的布尔禁用状态和原生隐私授权事件：

```powershell
$env:WXML_COMPILER = '你的微信开发者工具目录\resources\app.asar.unpacked\node_modules\wcc-exec\wcc.exe'
npm test
```

未指定编译器时，这两项渲染测试会明确跳过。Node 测试与模板编译不能代替手机网络、权限和实际 OLED 的真机验收。
