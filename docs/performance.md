# 二次性能复核

2026-11-06，同一台 i5-8300H / Windows 11 / Python 3.12.16 / CPU INT8。以下是软件测量；未包含真实开发板I²S、Wi-Fi无线链路或手机渲染。

## 本轮修复

1. **推理线程等待争用**：FunASR-ONNX 0.4.8默认允许ORT线程自旋，且关闭CPU内存arena。现构造模型时显式禁用自旋、启用可复用CPU arena，并缓存模型输入输出名称；不修改安装包。[ORT线程调优依据](https://onnxruntime.ai/docs/performance/tune-performance/threading.html)
2. **多余调度**：20ms传输包先按本来就存在的100ms VAD粒度合并，约50次/s的executor提交降至10次/s；stop尾包立即收尾，不等待补齐100ms。
3. **断句完整性**：VAD多个边界按序处理，绝对样本游标回填延迟起点；纯静音不进入在线ASR。移除任意12秒硬清缓存，保持连续语音上下文；总时长仍限制60秒。
4. **优先级竞态**：旧录音取消等待期间，如果新录音已占用ASR槽，旧任务不得恢复情绪进程或覆盖新状态。
5. **采音真实时间与丢帧**：DMA回调记录产生/丢失样本，读取任务按样本位置还原时间；覆盖会明确取消。发送每包后复查完整性，OLED正文缓存、同帧不重复I²C、慢帧不追赶。
6. **小程序视图桥**：字幕、情绪、音量统一归并，只保留一个在途更新；移除逐消息草稿重写和全文比较，限制历史总文字；入站消息不反复创建看门狗计时器，短暂连接不重置退避。

## ORT策略实测

相同5.5467秒官方WAV、3线程、相同480ms分块，各策略预热后重复5次，另按实时20ms包回放一次。所有策略识别文本一致。

| 策略 | 热推理中位数 | 解码调用P95 | 实时回放进程CPU* | 推理后1秒内CPU* |
|---|---:|---:|---:|---:|
| 上游默认自旋、无arena | 1159.1ms | 134.6ms | 130.4% | 34.4% |
| 仅关闭自旋 | 1685.9ms | 191.7ms | 43.7% | 0% |
| 关闭自旋并启用arena | 959.2ms | 125.1ms | 37.4% | 0% |

\* CPU按一个逻辑核100%计算，可超过100%；不是任务管理器按全机归一化的百分比。这里仅测在线模型。重复同输入的RSS增长为0～0.1MiB，arena保留工作内存以减少分配。耗时受主机负载与温度影响，不把一次最快值作为承诺；只关自旋在本次测试中变慢，因此同时验证了内存复用方案。

复现：`python tools/profile_runtime.py --threads 3 --repeats 5`。

## 真实TCP连续PTT与情绪交叉

真实Uvicorn/WebSocket连接、真实本地模型，两个订阅端。每次5.5467秒音频，连续5轮；轮间仅等待50ms，让情绪分析开始后再被新录音暂停。无假识别器，最终每句均为“欢迎大家来体验达摩院推出的语音识别模型。”。

| 项目 | 3线程（默认） | 4线程 |
|---|---:|---:|
| 松键到最终完成中位数 | 188.3ms | 243.5ms |
| 松键到最终完成P95 | 214.1ms | 352.8ms |
| 最慢一次最终完成 | 220.4ms | 376.6ms |
| 音频队列峰值 | 180ms | 360ms |
| 小程序通道ping P95 | 3.1ms | 7.4ms |
| 事件循环调度偏差P95 | 6.0ms | 16.8ms |
| 两端最终文字一致 | 5/5 | 5/5 |
| 情绪结果最终补齐 | 5/5 | 5/5 |

本轮保留3线程默认值，避免仅按批量吞吐把线程拉满。3线程5轮中主进程RSS从668.0到670.6MiB，情绪进程峰值369.9MiB；首次运行的懒分配不等于泄漏，五轮也不能证明无限时长无泄漏。每轮推理调度56次，未按278个20ms包逐次提交executor。

测量探针仅每250ms读取已知进程的内存；不在100Hz循环枚举全系统进程，避免测量本身成为主要负载。原始本机报告保存在被忽略的 `.local/gateway-stress-3.json` 和 `-4.json`。

复现：

```powershell
python tools/stress_gateway.py --rounds 5 --threads 3
python tools/stress_gateway.py --long --rounds 1 --threads 3
```

### 长时间按住录音

52.3735秒的单次PTT输入中包含8段同一官方语音及停顿：8个分句和8个情绪结果完整，两个TCP客户端文字一致。队列峰值320ms，低于1280ms过载窗口；主进程RSS从672.0到676.2MiB，峰值677.8MiB；ping P95为3.4ms。首个临时字幕1732.4ms，包含约610ms前导静音。结束消息后5.6ms完成是因为最后一句在尾部静音期间已完成VAD收尾，不能把它当成持续讲话时的松键延迟。

### 首字幕前滚对照

使用同一常驻模型交错测试0/300/480ms前滚，每种重复3次，文字均正确。300ms前滚令首字幕约1697→1398ms，但最终收尾约99→198ms，增加CPU工作；480ms前滚没有稳定改善首字幕。为优先保证松键后的速度，**默认仍为0ms**，没有把看起来更快的单项配置直接设为默认。前滚只允许回读本次PTT内、前一句真实端点之后的音频，字幕和情绪时间仍用真实VAD起点。

复现：`python tools/profile_preroll.py --repeats 3`。这些是同一官方样例的相位/延迟对比，不是普遍准确率或延迟保证。

## 小程序持续流量

30秒合成流量，160句历史、600次字幕修订、3000次音量、30次情绪，模拟120ms视图桥回调：`setData` **3930→151次**，累计payload **1,358,231→532,409字节**，待完成更新峰值 **17→1**，最终revision仍为600。极长快照最大payload **2,009,811→205,649字节**，避免超过1MB桥包。

这是Node协议/视图桥模拟，不是手机帧率。计数、资源上界和完整复现说明见 [小程序性能记录](../miniprogram/PERFORMANCE.md)。

## 实物边界

第三方WebSocket库的单次发送仍可能等待socket超时，4ms是包间工作预算而非单次网络发送硬时限；其内部有小块临时分配。采集线程与有界缓冲保护音频，过载会明确失败。DMA压力、物理首尾采样及I²C时序仍需上板验证；手机原生渲染需真机测试。

## 本轮检查结果

- Python后端31项回归，包含有序多端点、VAD回溯样本、EOF、连续25秒不硬切、取消/新录音交叉、受限前滚；真实模型和TCP压力另行验证。
- 小程序34项测试，包含视图桥资源上界、连接风暴、官方WXML渲染；官方WXSS编译通过。
- 最终固件PlatformIO构建成功，RAM 59,420字节（18.1%），Flash 1,482,615字节（22.6%）；native覆盖DMA积压/覆盖基线、PTT代次、缓存失效及发送预算回绕。
- ISR回调与timer/critical依赖通过ELF符号检查位于IRAM，stamp/guard位于DRAM。仍需真实硬件验证时序。
# 独立 PC 控制台与历史校对复核（2026-11-07）

PC 页面使用独立目录、进程和本机端口 8766，不导入或加载 ASR 模型。通过现有 WebSocket 订阅 8765；文字情绪线索在两个客户端计算，最多16处可见高亮并缓存结果。原文与校对文本共同计入 65536 UTF-16 单元预算。保存校对的 SQLite 工作放在线程池，保持在 ASR executor 之外；显示推送在录音或识别期间拒绝，并等待设备独立命令 nonce 的 ACK。

在本机使用同一份 5,546.7ms 官方普通话样例、真实 ONNX 模型和 TCP WebSocket、3个 ASR 线程、情绪识别开启，按20ms实时节奏重放，每组5轮。物理开发板与生产8765服务没有被软件重放客户端替换；测试使用隔离8767网关及8786控制台。

| 指标 | 无 PC 页面（1个软件订阅客户端） | PC 浏览器可见并接收实时字幕（共2个订阅客户端） |
|---|---:|---:|
| 松键后最终字幕中位数 | 183.2ms | 171.3ms |
| 松键后最终字幕范围 | 126.6–218.1ms | 169.2–193.4ms |

| 排队音频最大值 | 280ms | 260ms |

| 事件循环抖动 P95 | 5.9ms | 6.0ms |

| ASR主进程最大 RSS | 671.2MiB | 671.4MiB |
| 完成情绪数 | 5/5 | 5/5 |

两组10次最终识别均为同一正确样例文本，所有消费者的最终文本一致。这里未见明显识别延迟退化，不能把测试波动解释成 PC 页面提升速度；新增订阅确实带来少量 CPU 工作。有限样例不代表任意电脑、网络、物理麦克风或手机的时延保证。报告位于被忽略的 `.local/console-perf-baseline.json` 与 `.local/console-perf-browser.json`。

复现：先运行 `pc-console/server.py --port 8786 --asr-host 127.0.0.1 --asr-port 8767 --device-id perf-s3`；基线关闭测试页面，运行 `tools/stress_gateway.py --rounds 5 --threads 3 --port 8767 --local-token`。开启8786页面后再运行相同命令并加 `--startup-delay 20`，确认报告 `client_subscribers` 为2。`--local-token`只从已有本地文件读取口令，不打印口令。软件协议客户端不能验证 I²S、实体按键、OLED实物或微信真机。

历史校对、跨连接SQLite事务和最终UI全部完成后，又在PC页面开启状态串行复测5轮：最终延迟146.5–170.1ms，中位159.5ms；首条临时字幕中位1694.2ms，音频队列峰值220ms，ping P95 3.7ms，事件循环抖动P95 5.9ms。5轮文本一致，情绪5/5完成；两个订阅客户端均在场。最终报告为 `.local/console-perf-final.json`。不把这一轮较低数值解释为功能带来的性能提升。

完整回归为Python66项、小程序64项（含微信官方WXML编译渲染）、PC22项，均通过；WXSS官方编译与固件native也通过。固件0.1.1构建RAM59,420B、Flash1,488,127B。浏览器用独立测试网关和明确的测试替身验证保存、原文对照、原/校对两路推送ACK、二维码和安全文字渲染；这些UI验证不等同于真实OLED验收。

情绪改进仅从同一次 SenseVoice forward 提取7个标量候选，质量统计仅在原有单线程低优先级 SER 进程中执行；新录音仍暂停该进程。182次公开样例研究与官方解码器13/13一致性验证见 [情绪说明](emotion.md)，未虚称中文总体准确率提升。
