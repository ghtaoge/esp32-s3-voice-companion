# 验证记录

日期：2026-11-06。尚未烧录用户的开发板；以下软件与模型验证不能代替真实麦克风、手机与 OLED 验收。

## 硬件与环境

- Windows 11 x64，Intel Core i5-8300H（4核8线程）。
- Python 3.12.16，ONNX Runtime 1.23.2，FunASR-ONNX 0.4.8。
- CPU INT8，ASR内部线程3；VAD/标点各1线程；情绪独立进程1线程。
- 流式模型使用 `[5,8,4]`，中央分块480ms，保留左上下文。输入 PCM16/16000Hz/单声道。
- 模型文件由官方 ModelScope 下载，按上游 SHA-256 校验。具体文件版本与来源保存在下载生成的 `models/manifest.json`，权重和本机结果不上传。

## 真实模型测量

样例为 FunASR 官方仓库内 `asr_example.wav`，音频 **5.5467秒**，SHA-256：

```text
a1bd32dc78493c123f9625a66deee562aed2895f53fbc39f2cca3be7e6f4f20f
```

识别结果：`欢迎大家来体验达摩院推出的语音识别模型。`

| 项目 | 本次测量 |
|---|---:|
| 热流式 ASR 累计推理 | 1037.7ms |
| ASR实时率 RTF | 0.187 |
| 单次有效解码调用 P95 | 107.2ms |
| VAD累计处理 | 150.4ms |
| 标点 | 4.1ms |
| SenseVoice情绪/事件 | 937.2ms |

情绪原始标签为 `<|NEUTRAL|>`，声音事件 `<|Speech|>`，映射为 neutral/speech。模型没有返回置信度，本项目不生成一个“看起来合理”的分数。单一中性样例只能验证真实模型链路，不是情绪分类准确率评测。

模型测试同时确认：同PCM重置复跑一致、20ms与100ms包的VAD边界一致、20ms尾包能完成收尾。特征前端关闭随机dither以提高可复现性。

## 完整网关回放

将上述样例重复两次，中间加入1秒静音，构成12.0934秒的同次PTT录音。使用真实模型及两个WebSocket软件客户端，持续发送20ms包，最后发送松键结束消息。

| 项目 | 本次测量 |
|---|---:|
| 从开始发送到首字幕 | 1560.2ms |
| 松键结束消息到最终字幕完成 | 156.8ms |
| 最终分句 | 2句 |
| 两个客户端最终文本 | 完全一致 |
| 设置下发与设备ACK | 通过 |
| 延迟情绪补发 | 两句均 neutral/speech |

样例本身约有610ms前导静音，首字幕时间包含它。网关测量使用软件模拟开发板协议端，**不含真实 Wi-Fi 传输、I²S采样、OLED刷新或手机渲染时间**。数据代表本次环境与样例，不是所有录音的延迟保证。

复现命令（先安装开发依赖）：

```powershell
.\.venv\Scripts\python.exe tools/benchmark_models.py models/_samples/asr_example.wav
.\.venv\Scripts\python.exe tools/verify_gateway.py models/_samples/asr_example.wav --double
```

## 软件检查

- Python后端17项测试通过：音频首尾顺序、最终字幕覆盖、身份/设备校验、错误PCM、设置ACK、断线重连、存储有界、迟到写入、音频过载及慢客户端保护、配对PNG生成。
- 微信小程序：28项测试通过，包括官方WXML编译后渲染；官方WXSS编译通过。无编译器的CI会明确跳过这两项专有工具检查。
- PlatformIO：ESP32-S3 N16R8固件构建通过，静态RAM 57,340字节（17.5%），Flash 1,480,607字节（22.6%）；镜像信息确认16MB Flash目标。
- 本机C++测试：按键启动/消抖/重复按住、UTF-8、PCM饱和、首尾采样区间、计时器回绕、主循环阻塞时的按键事件积压与采音代次。采音起止由按键任务直接发布，不等待网络；旧代采集确认结束后才清理队列、允许下一代。
- OLED情绪与空闲状态在UI锁内按录音代次校验，旧情绪回包不能覆盖新的按压状态。
- `pip check`：通过；公开源码扫描：未发现真实凭据、AppID、模型、录音或本地配置被加入Git。
